# v1.4.0 — Faster re-runs and a run summary

**Date:** 2026-10-31
**Previous:** [v1.3.1](v1.3.1.md)
**Status:** Superseded by [v1.4.1](v1.4.1.md). Live-tested on 2026-10-31: skips of already-downloaded items were near-instant.

## Added

### Finished items are skipped without loading their pages

Before, each album, candid or video page was downloaded just to read the model name from its title, and only then was the database checked. On a profile with 154 candids already downloaded, that was 154 wasted requests every run.

Now the item's ID and model are read from its URL (`/girls/<model>/album/<id>/…`, `/videos/<id>/…`) and checked against the database **before** any request.

- **Albums, candid posts and blog posts** (`downloadAlbum`) check both the `album` and `candid` record types. IDs are unique across the site, so this can't skip the wrong item.
- **Videos** (`downloadVideoPost`) use the model from the profile sweep, or from the URL when there is one. A standalone `/videos/<id>/` URL has no model in it, so it still loads the page.
- **If the URL's model name doesn't match the history database's name** (for example, a slug like `mary-jane` versus a title of `MaryJane`), the early check finds nothing and the original page-based check still runs. Worst case is the old speed; it never wrongly skips.
- **New helpers:**
  - `knownDownloaded` checks the database without creating it, so a guessed model name never leaves an empty `.db` file behind.
  - `idAfter` reads the ID out of a URL.

### Run summary

Every run now ends with one line:

```
Done in 2m14s — Downloaded 3 · Skipped 151 · Failed 0 · 4.37 MB
```

- **Downloaded:** albums, candid posts, group comments and videos fully saved this run.
- **Skipped:** items already in the database or on disk, and posts with no images.
- **Failed:** the same items as the failure list printed after it.
- **MB:** the total of all images and videos saved this run.

### `SHOW_SKIPS=off`

This new optional setting in `.env` hides the individual `[skip]` lines, so a big profile doesn't scroll pages of grey. Skips are still counted in the summary, and the `[017/154]` counters on downloaded items still show where the run is.

## Changed

- All skip lines go through one helper, `printSkip`, which counts them and respects `SHOW_SKIPS`.
- `getModelDB` uses the new `modelDBPath` helper. The database location is unchanged.

## Tests added

- `TestIDAfter`: reads IDs from album, blog and video URLs.
- `TestKnownDownloaded`: finds recorded items, matches the right record types, and doesn't create a database for an unknown model.
- `TestPrintSkipCountsHiddenSkips`: hidden skips are still counted.

## Upgrading

- No `.env` changes are needed. `SHOW_SKIPS` is optional.
- The exe in the `-test` folder has been rebuilt. Copy it to the folder the watcher runs from (`D:\Users\Ron\Downloads\SGo-Scraper-master`). The early check reads the `modelsdb` folder next to the exe, so it uses the watcher folder's existing history.
