# v1.0.0 — Baseline

**Date:** before 2026-10-31
**Status:** Superseded by [v1.1.0](v1.1.0.md)

This is the code as it was before the 2026-10-31 review, recorded so later changes have something to compare against.

## Features

- Downloads photosets, candid posts, videos, blog posts and group-thread comment images.
- Sweeps a whole model profile from its base URL (`/girls/<model>/`): photosets → candids → videos → blogs.
- Uses up to 5 downloads at once, spaced out by `DOWNLOAD_DELAY_MS` (default 2000 ms).
- Keeps download history in SQLite at `<exeDir>/modelsdb/<model>.db` and `groups.db`.
- Optional `-z` flag zips a finished photoset.
- Saves videos through `ffmpeg` (`-c copy`).
- `Watcher.ps1` / `StartWatcher.bat` handle `.url` files dropped into `Incoming\`.
- Exits with code `429` when the site rate-limits it.

## Known issues (found in the 2026-10-31 review)

All of these were fixed in [v1.1.0](v1.1.0.md).

1. The `rscivid` cookie was never sent: `.env` uses `RSCI_VID`, but the code read `RSCIVID`.
2. The "already on disk" check matched on filename prefix only, so post `123` was skipped if `1234 - …` existed. This affected candids and videos.
3. Partly failed items were marked as downloaded and then skipped for good:
   - Albums were marked if even one image succeeded.
   - Multi-image candids and group comments were marked even if every image failed.
4. A download that broke partway left a truncated file that later runs treated as finished.
5. Group-thread images came out in random order (Go map iteration), so file numbering changed between runs.
6. Any non-2xx page (for example a 404 album) panicked and stopped a whole profile sweep, and the watcher then retried that URL every 30 seconds forever.
7. `defer db.Close()` inside the group-thread comment loop kept database handles open until the thread finished.
8. The README said Go 1.21+, but `go.mod` requires 1.25. Its "legacy migration" claim did not apply to albums.
