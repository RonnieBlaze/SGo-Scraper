# v1.2.0 — Resilience, safety checks and cleanup

**Date:** 2026-10-31
**Previous:** [v1.1.0](v1.1.0.md)
**Status:** Superseded by [v1.3.0](v1.3.0.md). It builds, passes `go vet`, and passes 14 unit tests. Live runs on 2026-10-31 confirmed the login check (`Logged in as: …`) and the retry logic: a 500 error on a candids listing page was retried and the sweep carried on. Other changes work in normal use but weren't tested specifically.

This release works through every follow-up item from the v1.1.0 review. The theme is failing gracefully: brief network problems are retried, one bad page no longer ends a run, expired cookies and mistyped URLs are caught up front, and the watcher no longer stops or blocks on a bad file.

## Fixed

| # | Problem | Fix | Files |
|---|---------|-----|-------|
| 1 | A failed listing (`?offset=`) page panicked and ended the whole run | The four pagination functions now share one helper, `getAllLinks`. A failed page is recorded, the links found so far are kept, and the run carries on. A repeated offset no longer loops forever | `crawler.go` |
| 2 | One timeout or 5xx error failed the whole item | `withRetry` makes up to 3 attempts, waiting 5 s and then 10 s. 4xx errors, HTML-instead-of-image responses and local file errors are marked `permanent` and fail at once | `http.go` |
| 3 | Expired cookies weren't detected | `checkLogin` runs before every download. It needs `SESSIONIDTOKEN` to be set and the home page to show a logged-in user (`sg-user_name`); otherwise the run exits with code `4`. `LOGIN_CHECK=off` skips it | `http.go`, `main.go` |
| 4 | The watcher ignored `.txt` files although the README said they worked | `.txt` files are picked up, using the first line that starts with `http(s)://`. Files with no URL go to `Incoming\Failed` instead of being re-read every 2 seconds | `Watcher.ps1` |
| 5 | A stalled `ffmpeg` download could hang forever | A video is stopped if its file doesn't grow for 2 minutes, or after `VIDEO_TIMEOUT_MIN` minutes in total (default 180) | `video.go` |
| 6 | A new HTTP client for every request | One shared client (`authedClient`) reuses connections. Cookies the site refreshes during a run are kept as well | `http.go` |
| 7 | Every image was saved as `.jpg` | The extension follows the `Content-Type` (`.png`, `.webp`, `.gif`, `.avif`). The on-disk check looks for every image extension | `http.go` (`saveImage`, `imageExtFor`, `existingImage`) |
| 8 | Unrecognised URLs were swept as a model profile | `routeFor` sorts the URL into one of the known page types, checking the host too. Anything else exits with code `5` before any request is made | `main.go` |
| 9 | Yearless album dates could land in the future around New Year | A date that would be in the future is moved back a year | `crawler.go` (`getAlbumDate`) |
| 10 | The 5-at-a-time download loop was copied three times (5 including single-image cases) | One `downloadImages` helper is used by albums, candids and group threads | `main.go` |
| 11 | No tests | `scraper_test.go` adds 14 tests: name cleanup, title parsing, pagination, album/group parsing (including image order), album dates, URL routing, on-disk matching, extension detection, retries, and image saving against a local test server | `scraper_test.go` |
| 12 | Housekeeping | Ran `gofmt` and `go mod tidy` (`modernc.org/sqlite` is now listed as a direct dependency), ran `git init`, and extended `.gitignore` | various |

## Also fixed while working on these

- **The watcher quit after its first error.** `break` inside a PowerShell `ForEach-Object` block exits the enclosing `while` loop too, so the first 429 or crash ended the watcher entirely. It now uses a `foreach` statement, so `break` only ends the current pass.
- **A response body was left open.** `getAlbumInfoImages` didn't close it on a non-200 reply.
- **A zip failure crashed the run.** A failed `-z` zip used to `panic`; it's now recorded as a failure for that album.
- **Profile URLs with a query string** (`/girls/bob/?ref=x`) built bad listing URLs. The profile base is now taken from the URL path.

## Changed behaviour

- **Login check before every run.** This makes one extra request to the home page. If it ever reports you as logged out when you aren't, set `LOGIN_CHECK=off` in `.env` and report it. It looks for `sg-user_name="…"` on the home page, which a live run on 2026-10-31 confirmed is there when logged in.
- **Retries print a line** such as `[retry 1/2 in 5s] <url> — <error>`.
- **New exit codes:** `4` (login check failed) and `5` (URL not handled).
- **Watcher:** exit `5` moves the file to `Incoming\Failed`; exit `4` keeps it and pauses 5 minutes.
- **Download errors include the label,** e.g. `Error: Downloading [0003/0040] — …`.
- **Code layout:** the networking code moved into the new `http.go`. `getContents`, which panicked, was removed, and `newAuthedClient` was replaced by `authedClient`.

## Exit codes

| Code | Meaning | Watcher does |
|------|---------|--------------|
| `0` | Everything downloaded (or was already downloaded). | Deletes the queued file |
| `3` | The run finished, but some items failed. | Moves it to `Incoming\Failed` |
| `4` | Login check failed. **New.** | Keeps it, pauses 5 minutes |
| `5` | URL not handled. **New.** | Moves it to `Incoming\Failed` |
| `429` | Rate-limited. | Keeps it, pauses 5 minutes |
| other | The run stopped early. | Keeps it, pauses 30 seconds |

## New settings (`.env`, optional)

| Setting | Default | Purpose |
|---------|---------|---------|
| `VIDEO_TIMEOUT_MIN` | `180` | The longest one video may take, in minutes |
| `LOGIN_CHECK` | on | `off` skips the login check |

## Not changed (possible future work)

- A 429 still exits the program, and the watcher waits 5 minutes. Backing off and resuming inside the program would avoid re-reading the listing pages.
- `ffmpeg` still doesn't get the session cookies, which only matters if a stream URL needs a login.
- The tests use hand-written HTML. Saving a few real pages under `testdata/` would catch site layout changes more reliably.
- The repository has no commits yet.

## Upgrading

- No `.env` changes are needed; the new settings are optional.
- The exe in the project folder has been rebuilt. To rebuild it yourself, run `go build -o SGo-Scraper-master.exe`.
- Existing `modelsdb/*.db` files and download folders work unchanged.
