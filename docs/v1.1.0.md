# v1.1.0 — Reliability fixes

**Date:** 2026-10-31
**Previous:** [v1.0.0](v1.0.0.md)
**Status:** Superseded by [v1.2.0](v1.2.0.md). Live-tested by the user on 2026-10-31 and working.

This release fixes the bugs listed in v1.0.0. The main change: an item is only recorded as downloaded when every file in it downloaded successfully.

## Fixed

| # | Problem | Fix | Files |
|---|---------|-----|-------|
| 1 | `rscivid` cookie never sent | Reads `RSCI_VID`; the old name `RSCIVID` still works as a fallback | `crawler.go` (`newAuthedClient`) |
| 2 | "Already on disk" matched by prefix only (`123` matched `1234 - …`) | Matches on `"<id> - "` exactly, using the new `findExistingEntry` helper | `utils.go`, `main.go`, `video.go` |
| 3 | Partly failed items marked as done | Albums, candids, group comments and videos are only recorded when every file succeeded | `main.go`, `video.go` |
| 4 | Truncated files left by interrupted downloads | Images and videos are written to `<name>.part` and renamed only when complete. The `.part` files are ignored by the on-disk checks | `utils.go` (`saveImage`), `video.go` |
| 5 | Group-thread images numbered in random order | Image URLs keep their order on the page (`orderedImgs`) | `crawler.go` (`getAllGroupThreadImageBuckets`) |
| 6 | One bad page stopped a whole sweep | Album, candid, blog, video and thread pages use `getContentsE`. Failures are logged and the run carries on | `main.go`, `video.go` |
| 7 | Group-thread DB handles stayed open until the thread finished | Each handle is closed right after use instead of with `defer` in the loop | `main.go` (`downloadGroupThread`) |
| 8 | README out of date | Go version changed to 1.25+; added notes on retries and exit codes | `README.md` |

## Changed behaviour

- **Retries fill in what's missing.** `saveImage` skips any image already on disk, so a re-run downloads only the missing files. As a side effect, albums now pick up files from before the database existed.
- **Multi-image candid folders are reused.** If a `<postID> - …` folder already exists, the missing images go into it instead of the whole post being skipped.
- **Group comments** count as done only when all of their images are on disk.
- **Candid posts** are checked against the database *before* the image list is fetched, which saves requests on posts that were already downloaded.
- **Failure summary.** Failed items are listed at the end of the run, and the program exits with code `3`.
- **Watcher.** On exit code `3`, `Watcher.ps1` moves the `.url` file to `Incoming\Failed\` instead of retrying it indefinitely.

## Exit codes

| Code | Meaning |
|------|---------|
| `0` | Everything downloaded (or was already downloaded). |
| `3` | The run finished, but some items failed. **New in this version.** |
| `429` | The site rate-limited the scraper. |
| other | The run stopped early (for example, a listing page could not be loaded). |

## New helpers

- `findExistingEntry(dir, prefix, wantDir)` (`utils.go`): finds an existing file or folder for an item and ignores `.part` files.
- `recordFailure(item, err)` and `failedItems` (`utils.go`): collect failures for the summary at the end of the run.

## Not changed (possible future work)

- A new HTTP client is still created for every request, so connections aren't reused.
- `modernc.org/sqlite` is still marked `// indirect` in `go.mod` (`go mod tidy` would fix it).
- `ffmpeg` doesn't get the session cookies, which only matters if a stream URL needs a login.
- A listing page that fails to load still stops the run (exit code `2`, from a Go panic).
- The source files are not `gofmt`-formatted. This was already the case in v1.0.0.

## Upgrading

- No `.env` changes are needed. `RSCI_VID` now works as the README describes.
- Rebuild with `go build -o SGo-Scraper-master.exe`. The exe in the project folder has already been rebuilt.
- Existing `modelsdb/*.db` files work unchanged.
